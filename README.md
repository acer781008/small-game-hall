# 小遊戲館 V1.4｜同局續玩＋A/B 獎品模式

目前整合：賓果、數獨、翻牌、貨架整理。

## V1.0 這次修改

### 1. 永久資料保存
正式部署時，只要在 Render 服務設定 `DATABASE_URL`（PostgreSQL 連線字串），以下資料會寫入 PostgreSQL，不會因為 Web Service 重啟、休眠或重新部署就消失：

- 目前活動碼
- 開賽日期＋時間、結束日期＋時間
- 共用備註
- 各遊戲開放／關閉
- 四款遊戲設定
- 獎品項目、剩餘數量、啟用狀態
- 每位玩家最多得獎次數
- 得獎紀錄
- 玩家參與紀錄（每款遊戲誰玩過、玩幾次、最後遊玩時間）

如果沒有設定 `DATABASE_URL`，系統仍可本機測試，但會使用 JSON 檔；主控頁會顯示警告「本機 JSON」。

資料庫表格會由程式第一次啟動時自動建立，不需手動建表。

### 2. 賓果圖片修正
整合到 `/games/bingo` 後，原本玩家盤面的圖片網址仍指向 `/farm/...`、`/mahjong/...`，所以 Render 上會出現破圖，只剩「圖案 110」這類替代文字。

V1.0 已改成：

- `/games/bingo/farm/...`
- `/games/bingo/mahjong/...`

農作物與麻將圖都會從賓果自己的資料夾正常載入。

### 3. 主控頁資料保存狀態
主控後台會顯示：

- `💾 永久資料庫：已連線`：正式永久保存已啟用
- `⚠️ 本機 JSON：正式上線前請設定 DATABASE_URL`：目前仍不是永久保存

## Render 環境變數

必要：

```text
ADMIN_PASSWORD=你的主控密碼
DATABASE_URL=你的 PostgreSQL 連線字串
```

如果你的 PostgreSQL 明確要求 SSL，可另外設定：

```text
DATABASE_SSL=require
```

若使用不需要 SSL 的本機 PostgreSQL：

```text
DATABASE_SSL=disable
```

## 本機測試

沒有設定 `DATABASE_URL` 也可以先測：

```bash
npm install
npm start
```

開啟：`http://localhost:3000`

主控：`http://localhost:3000/admin-login.html`

## 更新既有 GitHub 倉庫

如果你已經有 `small-game-hall` 倉庫，不用重新建倉，也不用重新上傳所有圖片。

把「V1.0 更新檔」覆蓋到原本的遊戲館資料夾後，在 Git Bash 輸入：

```bash
git add .
git commit -m "V1.0 永久資料庫與賓果圖片修正"
git push
```

Render 若已連著這個 GitHub 倉庫，push 後會自動重新部署。

## V1.4 同局續玩＋A/B 獎品模式

### 1. 重新整理仍回到原本尚未完成的那一局
四款遊戲統一處理：

- 賓果、數獨、翻牌、貨架整理開始後會保留「進行中」狀態。
- 同一裝置／瀏覽器重新整理或關掉頁面再開，會回到原本那一盤。
- 倒數沿用原本開始時間，不會因重新整理重新計時。
- 玩家操作進度會保存在瀏覽器本機儲存空間；重新整理會恢復已點格、已填數字、已配對卡片、貨架目前排列。
- 重新整理不會增加遊玩次數。
- 只有本局完成、時間到或活動失效後，才可以開始下一局。

> 此功能針對一般頁面重新整理／關閉後重新進入。若瀏覽器清除網站資料，裝置端的操作進度可能無法還原。

### 2. A／B 兩種獎品發放模式
主控「獎品設定」可選：

- **A｜共用獎池**：不分遊戲，完成任一開放遊戲即從全部剩餘獎品中隨機獲得。
- **B｜指定遊戲獎池**：每個獎品可指定一款或多款遊戲；玩家完成哪款遊戲，就只從該遊戲可獲得的剩餘獎品中隨機抽取。

B 模式若某款遊戲已沒有符合的剩餘獎品，完成後會顯示該遊戲獎品已兌換完畢，不會抽到其他遊戲的獎品。

### 3. 玩家查看目前獎項
玩家首頁新增 **「🎁 查看目前獎項」** 按鈕：

- A 模式直接列出全部目前獎品與剩餘數量。
- B 模式依賓果／數獨／翻牌／貨架整理分組顯示。
- 已領完的獎品仍會顯示「已兌換完畢」。

### 4. 暫不加入玩家自選難度
V1.4 仍沿用目前由主控設定遊戲難度的方式；玩家自行選擇難度留待後續版本再新增。

## V1.4.1 時間到可重試＋完成後返回遊戲廳
- 四款遊戲統一：時間到未完成時，顯示「🔄 重新開始」與「🏠 返回遊戲廳」。
- 成功完成後，顯示「🏠 返回遊戲廳」，不再需要使用瀏覽器上一頁。
- 返回遊戲廳會保留目前活動碼。

- 主控「玩家參與紀錄」仍然每次真正按開始都會記錄，因此重試也會正確增加參與次數。
